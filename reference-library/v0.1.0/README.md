# 离线匿名参考库 0.1.0

用于按**电机定子规格＋KV＋桨叶几何参数**查找同类台架候选数据。例如电机输入 `2306` 和 `1850`，无需填写厂商或品牌。数据行不保存厂商、产品名称、来源或链接；许可署名单独保存在 `LICENSE-ATTRIBUTION.md`，发布时须随附。

这是候选台架库，不是已经验证的实飞续航库。导入后不能直接宣布所有配置都能算续航，更不能据此给电池健康评分。

## 文件与字段

七份数据 JSON 都有 `schemaVersion`、`libraryVersion`、`items`。`manifest.json` 记录数量、能力边界和七份文件的 SHA-256；它不含数据来源链接。

| 文件 | 主要字段／用途 |
| --- | --- |
| `motor-catalog.json` | `stator` 字符串、`kv` 数值、`anonymousVariants`、`benchPoints` |
| `propeller-catalog.json` | `diameterIn`、`pitchIn`、`blades`、`anonymousVariants` |
| `bench-curves.json` | 匿名 `id`、定子／KV、`cells`、`propeller` 或 null、条件标记、`points` |
| `constant-voltage-segments.json` | 匿名 `id`、父组 `curveId`、定子／KV、桨叶几何、`cells`、`voltageV`、条件标记、推力／功率点 |
| `coverage.json` | 每个定子／KV 的点数、匿名组数、已知桨叶组数、同电压段数 |
| `flight-references.json` | 当前 `items: []`，不得用台架数据填充 |
| `style-calibrations.json` | 当前 `items: []`，不得填入经验 k |

台架点的字段：`voltageV`（V）、`currentA`（A）、`thrustGf`（克力）、`electricalPowerW`（W）、`rpm`（数值或 null）、`throttlePercent`（数值或 null）。功率是表列 V×I 的结果，保留六位小数只是数值格式，不代表测量精度。

所有曲线保留 `escInclusion: "unknown"`、`assembly: "unknown"`、`temperatureC: null`、`flightValidation: "none"`。完整曲线的 `eligibility` 是 `anonymous-category-candidate`；同电压段的标记是 `numeric-interpolation-only`。这些是**用途限制**，不是质量认证。

定子规格必须保存为字符串：`0802`、`2306`、`2806.5`。不要将 `2306` 当作可以连续插值的数值。KV、桨叶尺寸和其他测量值可以是小数；原库的精度不应为适配界面而被擅自四舍五入。

## 使用边界

1. 定子、KV、桨径、螺距、叶片数、节数须逐项匹配。几何相同仍可能有不同桨型、电机绕组和测试条件，只能称“同类候选”。`anonymousVariants` 和曲线数量不是独立样本数量。
2. 使用一个同电压段时，只能在它的推力覆盖区间插值。不同电压、不同匿名组之间不得拼点、平均或外推。没有电压匹配规则的独立依据，就只列出各测试电压下的候选信息，不能把起飞前电压当作全程负载电压。
3. 同电压是“表列值相等”，不证明实验电压没有波动。同电压段通过数值检查，仍不证明实验准确、包含电调损耗或适用于装机状态。
4. 普通四轴悬停的单电机需求约为起飞重量的四分之一（gf）；牛顿形式为 `(重量g/1000)×9.80665/4`。这只是静态近似，不能自动用于巡航、花飞、竞速、有风、涵道或 Whoop。
5. 当前未知的电调损耗、装配、环境等条件不能自动改成“已确认”。用户也不能仅凭自己的机型信息补证原台架条件。现有严格台架时间分支的要求没有因此被满足。
6. 可以输出“同类台架候选功率”；多组候选分别计算后得到的最小／最大值只叫“候选值范围”，不是置信区间、正常范围或预计误差。也不能认为它一定覆盖用户实际电机。
7. 只有满足适用性与功率定义要求后，才讨论 `P整机≈4×P单电机＋P辅助`、`t分钟≈60×可用Wh/P整机`。辅助功耗未知不默认 0，可用 Wh 不默认标称能量的 80%。本包自身不具备产出可信续航时间的完整条件。
8. 没有独立的飞行方式校准就不设通用 k；没有独立实飞验证就不评级“正常／偏短／较长”。保留软件原有的等效续航、电池分析及“参考不足”降级。

## 整理与核查

原输入 6,161 个台架点中，10 个未满足正数／有限数要求，116 个未通过 1–8S 节数格式范围筛选；保留 6,035 个。116 个被筛除点不能全部解释为大于 8S，也可能是缺失或未支持格式。未识别的桨叶不猜测几何。整理过程保留匿名测试组隔离，不把厂商宣传值变成整机实飞时间。

在项目根目录离线核查：

```powershell
& .\.tools\node.exe reference-library/v0.1.0/tools/validate.mjs
```

工具无需额外依赖。验证内容包括字段白名单、无品牌／来源字段、单位、V×I、计数守恒、同电压与父组隔离、文件校验和及解析边界夹具。结果见 `VALIDATION.md`。验证不包含整机准确性、原始实验复测或品牌去除后的可迁移性证明。

`tools/build.mjs` 只用于显式维护数据时从固定快照重新整理；地址与原始内容校验值见独立许可附件。构建用法为 `node tools/build.mjs --base-url <附件中的固定快照地址>`。不要把该脚本或联网抓取加入程序启动流程。

导入软件的完整任务说明见 `INTEGRATION-PROMPT.md`。本次仅创建数据包和说明，没有改动或重打包应用。
