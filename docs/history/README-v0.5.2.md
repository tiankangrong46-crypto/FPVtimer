# 穿越机续航表现评估工具

Windows 本地单页工具，Tauri 2 + Vue 3 + TypeScript + Vite。用户飞完后输入配置和本次实测数据，获取有依据的续航参考；运行时无需 Node、Rust 或联网，输入关闭后不保留。

本文面向使用者和开发者；后续 AI 接手先读 [AGENTS.md](AGENTS.md)。当前涵道／圈圈机假设见 [docs/ALGORITHM-0.5.2.md](docs/ALGORITHM-0.5.2.md)，理想后备物理依据见 [docs/ALGORITHM-0.5.0.md](docs/ALGORITHM-0.5.0.md)，粗估基础见 [docs/ALGORITHM-0.4.0.md](docs/ALGORITHM-0.4.0.md)，匿名匹配见 [docs/ALGORITHM-0.3.0.md](docs/ALGORITHM-0.3.0.md)。历史产物按版本保留，新版产物和验收写入 `outputs/v0.5.2/`。

- 已完成独立计算模块、中文单页界面、输入校验、Windows x64 EXE 和 NSIS 安装包。
- 正式实飞参考库 `enduranceReferences`、独立工况k库 `styleCalibrations` **均为空**。没有匹配实飞记录就不生成独立参考时间；有充分可选依据时，可显示明确标识的模型粗估或本次等效时间，主评级仍为“参考不足”。
- 参考不足是有意保留的结果，不是待用演示数据填补的界面缺陷。代码中的其他评级分支仅以人工测试夹具验证，尚无合格实飞参考验证其预测准确性。
- 新分支：独立实飞中位数／验证区间 → 同配置台架功率与可用Wh模型 → 本次平均电流与目标Q等效 → 参考不足。时间推算不得自证本次正常。台架表支持在可选分析中本地录入；非悬停无独立k时不能套悬停时间。
- 已接入匿名候选库0.1.0：289个定子规格／KV组合、149个桨叶目录几何、1054匿名曲线、6035点、519同电压段。标准模式只展示同类候选功率；新增粗估模式可以在明确假设下组成各测试电压的悬停等效场景。未知条件保留，不能替代严格模型或启用评级。2306／1850KV暂无对应候选，支持自由输入库外规格。
- 粗估优先尝试有依据电流＋目标Q／用户容量比例，随后用匹配匿名功率＋有依据Wh或标称能量假设；无匹配时可走理想悬停后备，不再要求每种电机都有记录。比例未知可给“假设标称能量全部可用”，辅助未知可给“仅计推进功耗”；非悬停无用户倍率只给无风悬停等效。超出匹配推力或模型范围仍停止对应估算。
- 后备采用重量与总桨盘面积的理想动量模型，固定标准海平面、正方形独立桨盘假设；适用的匹配台架优先。涵道／Whoop新增理想基线＋13%用户假设场景，不使用开放桨匿名台架，不计算涵道增升和气流干扰。可填0至小于100%或未知，未知时只给未扣推进损耗理想值。理论公式与软件核实不等于实机精度已验证，小损耗不保证接近实飞。
- 有时间时突出时间和主要假设，“尚不能评价本次是否正常”次要显示；粗估、等效和正式评级分别处理。
- 可选数据充分时，保留平均负载压降和停桨前后电压对照；回弹解释新增“时间接近、期间电量变化可忽略”的用户依据确认。
- 不提供账号、云服务、数据库、历史记录、自动更新或联网 AI。不因续航短或某个内阻值直接判定电池损坏，不输出电池健康百分比。
- 0.5.2通过135项计算、22项页面、类型检查及26项实际EXE离线模拟检查；实际EXE及打包结果见[本版验收记录](outputs/v0.5.2/验收记录.md)。没有安装新版或验证整机预测精度。旧版检查仅作历史归档。

## 使用

安装版：`outputs/v0.5.2/FPV-Endurance-0.5.2-x64-setup.exe`，供用户自行双击安装。本次不自动安装新版。安装包包含微软 WebView2 完整离线组件，缺少运行时的电脑无需下载安装引导器；实际安装可能受权限或系统策略限制。

独立程序：已有 WebView2 时可直接运行 `outputs/v0.5.2/FPV-Endurance-0.5.2.exe`。此文件本身不包含 WebView2；分发时同附同目录`LICENSE-ATTRIBUTION.md`。安装版也随附独立许可资源。

旧版安装包约208MiB，独立程序约2.98MiB，原始文件与`outputs/v0.1.0/`备份均保留。此前安装到`%LOCALAPPDATA%\FPV Endurance`的是0.1.0，不因新版打包而自动升级。目标为Windows10/11 x64，实际验证环境为Windows11 x64。

1. 填写飞机、电池和本次飞行数据。机架轴距单位mm，桨径和螺距单位英寸；起飞重量包含电池与载荷。
2. 可选电池分析可整体跳过。数值未知请填“未知”或“不清楚”；零会作为零读数处理。
3. 点击“评估本次飞行”，也可在表单中按 Ctrl+Enter。
4. 结果旁可展开依据和来源。修改任意输入会使旧结果失效，需要重新评估。

需要假设时间时选“粗估模式”，在主表单“飞机结构”选择开放桨／涵道／圈圈机，按需在可选分析调整“粗估假设”。推进损耗分别默认8%／13%／13%（用户假设），其他假设初始为空／未知，不预填80%、0W或通用飞行倍率。LiPo标称能量使用3.7V／节；LiHV按标签选择3.80／3.85V，未知时不能从容量算Wh，但仍可用有依据Wh或Q。各测试电压的场景、匿名编号和未知条件可展开查看。

**没有独立参考不代表不能计算有条件的等效／模型时间，但这些时间不能充当本次正常评级的依据。** 不用标称容量的80%、任意k或电压差线性换算补齐缺口，不提供电池健康百分比。

粗估容量比例是用户显式假设；未知比例只在明确标识的“标称能量全部可用”场景中使用全标称量。未知辅助不被视为设备0W，而是另给未计辅助负载的推进场景；零倍率／非法值不当未知。场景范围不是置信区间、经验证误差、实际可飞时间、保证时间或安全上限。

## 输入和结果约定

| 内容 | 单位／处理方式 |
| --- | --- |
| 起飞总重量 | g，含电池和全部载荷，最多一位小数。 |
| 机架轴距 | mm，区别于桨叶直径；电机 KV 仅参与配置识别，不单独推算准确功率。 |
| 电机定子规格 | 字符串，例如0802、2306、2806.5；不要求品牌，可自由输入。未知只跳过类别候选。完整型号仅在可选人工精确台架使用。 |
| 桨叶 | 直径、螺距使用英寸，叶片数为整数；也可用具体型号代替三项规格。 |
| 电池 | LiPo / LiHV，标称容量 mAh，串联节数为 1–8 的整数。 |
| 实际飞行时间 | 整数分钟和秒；秒 0–59，总时间必须大于零。 |
| 电压 | 起飞前、落地停桨后使用整包 V，最多三位小数。 |
| 内阻 | 平均单节 mΩ，最多一位小数，例如 3.5；不是整包内阻。 |
| 测量时点 | 落地后测量间隔、负载读数距停桨时间、停桨后测量间隔分别记录，不能混为一项。 |
| 空、零、未知 | 分别保留；必填非法阻止评估，可选非法／未知仅跳过对应分析并提示，不猜值。 |

新增的内阻测量方式／设备、电流／消耗量来源和停桨测量时点统一放在“可选电池分析”，全部允许未知。环境温度允许负数，风况允许未知。

0.2.0在同一区域增加配置分组、目标可用Q／Wh及来源、目标区间状态／时点／适用性，以及可折叠台架数据录入。空、零、未知仍区分；未填可选项不阻止基本流程。台架表为工程原始数据转录，每列最多三位小数，需主动选择gf／N单位，不预设单位或任意k。

0.3.0增加精确库内几何选择，包含目录与同电压段的几何，不把1.22等原值舍入。选择后手输几何停用但原始字符串保留；返回手输可恢复。几何相同、同定子和KV不保证同款或相同效率。候选信息折叠在结果下方，显示测试电压、匿名ID与未知条件；输入改变使旧结果失效。

0.4.0粗估假设中的容量比例和辅助功耗最多一位小数，倍率最多三位小数且必须为正；明确0W与未知分别标注。涵道／Whoop不套开放桨匿名台架；0.5.2新增另行标识的理想基线假设场景。原严格模型继续需要完整型号、明确电输入定义、辅助／能量依据及适用的独立k，不能借粗估假设绕过。

0.5.0在同一区域增加“理想后备模型推进损耗假设”，允许未知／0至小于100%的一位小数；0.5.1按用户要求预填8%，重置后恢复8%，始终标为假设。2306／1850等库中无匹配组合可在普通开放桨、已知桨径且模型范围内走理想后备；当前桨盘相接／重叠、远尾流低马赫数条件不成立、已有匹配但推力超覆盖时停止。理想模型不核实真实电机最大推力，不能保证实际悬停或飞行时间。

主结果只有续航表现、可信时才出现的参考时间、以及一句原因。压降／回弹仅在依据充分时显示；公式、参与计算的输入、跳过原因和来源折叠展示。没有参考时也能完成“填写→校验→评估→结果”流程。

## 源码与构建

- `src/App.vue`：表单、结果、折叠说明和交互；修改输入使旧结果失效。
- `src/MeasureField.vue`、`src/style.css`：通用输入控件和本地样式。
- `src/domain/types.ts`：原始输入、读数状态和结果类型。
- `src/domain/validation.ts`：解析校验，区分空／未知／零／非法。
- `src/domain/analysis.ts`：唯一计算和评级实现，界面与 Rust 不复制算法。
- `src/domain/reference.ts`：全条件匹配、中位数、独立验证区间及记录隔离。
- `src/domain/bench.ts`：gf／N转换、四轴推力、覆盖内功率插值、Wh／W时间换算。
- `src/domain/endurance.ts`：四分支选择、台架适用性、目标可用量和本次等效时间；由analysis统一调用。
- `src/domain/stator.ts`、`category-bench.ts`：规格字符串、精确类别检索、同电压段逐条插值；不产生续航时间或评级。
- `src/domain/rough-estimate.ts`：粗估假设、标称能量、等效与逐段场景范围；复用既有单位／插值／Q/I与Wh/W公式，不产生正式评级。
- `src/domain/ideal-hover.ts`：四个独立桨盘的唯一理想功率与用户损耗转换；标准大气假设、量纲和边界来源见0.5.0文档。
- `src/data/reference-library.ts`：本地库类型、结构／一致性校验、只读加载与不可用降级；直接引用`reference-library/v0.1.0/`，没有第二份产品数据。
- `src/data/references.ts`：本地来源审查、模型来源和空的合格参考库。
- `docs/METHOD.md`：方法、公式、准入条件、参与计算的输入。
- `tests/domain.test.ts`：人工夹具和评级边界测试；不是实飞证明。
- `tests/branches.test.ts`：独立参考、台架、工况k、等效与降级分支；全部完整模型夹具均为人工数据，不进入产品。
- `tests/library.test.ts`：7份真实库校验和、匿名边界、真实段插值、隔离、缺失／损坏及原有分析降级；不证明整机精度。
- `tests/rough.test.ts`：115项中的新增18项，验证假设、范围方向、未知、化学标称、工况／电压隔离与不评级；不证明预测精度。
- `tests/ideal.test.ts`：20项解析算例、四桨面积／单位、缩放、8%／13%结构默认、假设隔离、损耗、匹配优先、重叠及低马赫数边界和回归；135项总数包含全部历史测试。
- `src/domain/structure.ts`：飞机结构与分组／用户损耗默认值的唯一映射；切换重填8%或13%。
- `scripts/ideal-model-audit.mjs`：复用公式只读诊断已知几何2943点，记录表格与理论假设的不一致；不产生默认校准值、不导入产品库。
- `tests/real-data.test.ts`、`tests/fixtures/`：公开实测电流片段及归属说明，只验证电量／平均电流换算，不验证穿越机续航精度。
- `tests/ui/form.spec.ts`、`playwright.config.ts`：页面自动测试。
- `src-tauri/src/main.rs`、`src-tauri/tauri.conf.json`：Rust 窗口与 Windows 打包配置，无业务算法副本。
- `scripts/build.ps1`：测试、生产构建、NSIS 打包并复制交付 EXE。
- `scripts/Use-Toolchain.ps1`：仅当前进程使用项目内 x64 Node／Rust。
- `scripts/desktop-smoke.mjs`：连接临时 CDP 端口，验证真实 EXE 的 WebView2 流程。
- `outputs/`：交付 EXE、预览、方法说明、验收记录和桌面检查 JSON。

`.tools/`、`node_modules/`、`dist/`、`src-tauri/target/` 等为忽略的工具／生成目录，不能作为唯一源码来源，也不能假定换电脑后仍然存在。当前 Git 尚无初始提交，源码和交付文件均有未跟踪内容，不要用清理命令删除。

环境：Windows 10/11 x64、x64 Node.js 22.22+、npm、Rust MSVC、Microsoft C++ Build Tools（C++桌面开发与Windows SDK）。项目当前安装了仅供开发的本地 Rust 与 x64 Node，在 `.tools` 中，不改变系统 PATH。这些开发工具不进入安装包。npm 和 Cargo 依赖分别由 `package-lock.json`、`src-tauri/Cargo.lock` 锁定。

本机系统 Node 为 ia32，曾导致 Vite 原生绑定加载失败；不要只检查系统是 64 位就认定 Node 也是 64 位。TypeScript 已固定为 5.9.3：此前 TypeScript 7 与当前 `vue-tsc` 不兼容，不要无理由升级依赖。

## 复核实际桌面程序

`npm.cmd run test:ui`验证开发页面，不能代替真实EXE验收。桌面脚本需临时调试端口，连接实际Tauri页面；会填人工数据、清空表单，并写入当前`outputs/v版本/`的`desktop-checks.json`和预览PNG，不覆盖旧版归档。

```powershell
. .\scripts\Use-Toolchain.ps1
$taskExe = Join-Path $PWD 'outputs\v0.5.2\FPV-Endurance-0.5.2.exe'
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9224 --disable-background-networking --disable-component-update'
$env:WEBVIEW2_USER_DATA_FOLDER = Join-Path $PWD '.tools\desktop-test-profile'
$env:FPV_DESKTOP_EXE = $taskExe
$taskProcess = Start-Process -FilePath $taskExe -WindowStyle Hidden -PassThru
# 等待程序窗口就绪，再执行：
node scripts/desktop-smoke.mjs
# 验收结束后正常关闭该专用窗口，再清除当前会话临时变量：
Remove-Item Env:\WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS -ErrorAction SilentlyContinue
Remove-Item Env:\WEBVIEW2_USER_DATA_FOLDER -ErrorAction SilentlyContinue
Remove-Item Env:\FPV_DESKTOP_EXE -ErrorAction SilentlyContinue
```

正常启动不启用调试端口，不要将上述调试参数写入产品配置或系统环境。验证安装版时，把 `$taskExe` 换成已经核实存在的安装版 EXE 路径。离线模拟通过不等于物理断网或全新系统验收通过。

## 限制

目标为Windows10/11 x64。本机Windows11验证不能替代Windows10、不同缩放、ARM64或全新无WebView2系统的验收。没有独立实测验证整机模型预测、工况k或正常评级区间的准确性；公开电流数据只验证单位换算。程序未签名，新版没有自动安装，按版本验收记录区分已通过和未验证。

下一步有实际价值的验证是：在干净、无 WebView2 的 Windows 环境测试首次离线安装，并寻找满足全部可比条件的普通穿越机实飞数据。这里记录的是待办，不代表已获准扩大产品范围或已经验证完成。
